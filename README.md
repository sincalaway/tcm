# 本草经方

“本草经方”是一套用于中医本草、经方和古籍文本学习的书斋式检索网站。它面向文献研读与知识整理，不提供诊断、处方、剂量或自行用药建议。

## 已实现能力

| 模块 | 当前能力 |
| --- | --- |
| 本草索引 | 支持药名、别名、传统功用搜索，并按类别、药性、归经筛选。 |
| 经方研读 | 支持方名、出处、条文、药味检索，并提供药名与条文症候词的多关键词学习检索；当前目录中的《伤寒论》方剂均可直达已编目的具体条文。 |
| 古籍文献 | 支持书名、作者、类别筛选；《伤寒论》已扩充太阳、阳明、少阴、厥阴与差后劳复篇的章节内条文索引，并通过中文维基文库公开接口检索原文标题与摘要。 |
| 我的书案 | 登录后可收藏条目、创建/编辑/删除学习笔记、记录古籍阅读进度、设定学习目标与管理站内复习提醒，并可将收藏、笔记和进度本地导出为 Markdown 或 JSON。 |
| 通知中心 | 独立查看复习提醒记录，可按全部、待阅、已阅状态与起止日期筛选并标记已阅。 |
| 学习路线 | 首页与个人书案展示路线完成度、平均阅读进度及书签、朱批等学习成就。 |
| AI 学习助手 | 基于当前本草、经方或章节上下文进行学习性解释；支持个人历史会话、手动长对话摘要、关键词检索、受控近期上下文、内置服务、本地或网络 OpenAI 兼容端点。 |
| 个人知识库 | 登录后可上传、检索、下载和移除自己的 TXT、Markdown 与 PDF 学习资料；文件字节保存在对象存储，数据库只保存元数据与文本预览。 |
| 古今衡重与煎煮研读 | 在经方页提供两、铢、斤、升、合、斗的多口径学习换算，并可按输入药味生成候选“先煎 / 后下 / 武火文火”核对清单；显示计算或资料来源，且不自动决定时长、加水量、分服次数或服用时间。 |
| 经方组合实验台 | 可在目录方剂上增减已编目药味，直观对比类别、药性、五味、归经索引和特殊煎煮候选项；对已有公开原典数量档案的方剂，同步展示药味古制数量与不同衡重研究口径的换算。枚、容量与质量分别保留，新增药味不自动推定数量；不产生处方、剂量、适应证或个体化加减建议。 |
| 条文线索匹配 | 可将症候词与自我观察角度转为《伤寒论》标题、摘录及关键词检索，并直达对应条文；支持常见口语症状词映射和并见线索对读提示，不判定体质、不诊断疾病、不推荐经方或用药。 |
| 来源治理 | 药材条目保留药典在线目录入口；古籍与方剂条目维护来源名称、来源标识与来源链接。 |

## 数据维护

首批结构化目录位于 `server/catalogSeed.ts`，并在首次目录请求时写入数据库。新增或修订药材、方剂、典籍、章节时，应同时维护条目的名称、稳定 slug、来源名称与 `sourceUrl`，并运行以下命令：

```bash
pnpm check
pnpm test
pnpm build
```

公开全文检索使用中文维基文库的 Action API；页面仅呈现查询结果的标题、摘要、时间与原站链接。对于药典在线等未提供明确第三方数据授权接口的来源，本站只保留目录与跳转入口，不复制受限标准正文。

### 《伤寒论》条文映射维护

《伤寒论》的条文级记录由 `shangHanPassageSeed` 维护；每条记录必须具备篇章标题、站内条文序号、学习摘录、检索词、出处标记与原站链接。`formulaPassageSeed` 将经方 slug 显式映射至条文，`primary` 为详情页默认直达入口，`related` 为补充对读入口。原典页在维基文库标记有校勘状态，因此站内只保存必要的学习摘录和链接，不以其替代原典或作出临床解释。[1]

当前已编入太阳病 11 条、阳明病 10 条，并补充少阳、发汗吐下后、少阴、厥阴、霍乱与差后劳复篇的学习条文。测试会检查每一条目录内《伤寒论》方剂至少拥有一条明确映射；扩充时仍应先核验原典，再维护种子和对应测试。[1]

## 学习目标与复习提醒

登录用户可在“我的书案”新增学习目标。目标可按**已完成路线步骤**、**已记录的古籍续读条目**或**研读笔记数**自动计算，因而不会为了完成统计而创建虚假学习记录。

复习提醒是用户主动创建的站内提醒：选择间隔天数和本地时刻后，平台每天进行一次到期检查；满足间隔时，书案会出现待复习提示，可标记为已阅。暂停或删除提醒会同步暂停或删除对应的定时任务。系统不会自动代替用户创建提醒，也不会发送未在产品中配置的外部通知。

通知中心位于 `/notifications`，只读取当前登录用户的提醒事件。页面可按已读状态和到期时间筛选；“标为已阅”仅更新当前用户本人事件，不会影响提醒规则或其他用户记录。

## AI 学习助手配置

AI 学习助手默认使用项目内置服务，并且只接受当前页面提供的标题、原文摘录与学习提示作为上下文。服务端提示词明确排除个体诊断、病情判断、处方、剂量和用药建议；这项功能仅用于术语、文本结构、出处线索和后续检索方向的学习整理。

如需接入 OpenAI Chat Completions 协议兼容的外部模型，可在项目环境中任选配置本地或网络端点。两类端点均为**可选项**；未同时提供地址和模型名时，前端不会显示该选项，自动模式将安全使用内置服务。请仅通过项目的秘密管理界面或安全环境变量注入这些值，不要提交到仓库。

| 场景 | 必填环境变量 | 可选环境变量 | 行为 |
| --- | --- | --- | --- |
| 本地 OpenAI 兼容服务 | `LOCAL_LLM_BASE_URL`、`LOCAL_LLM_MODEL` | `LOCAL_LLM_API_KEY` | 调用 `{BASE_URL}/chat/completions`；适用于自托管或局域网模型服务。 |
| 网络 API | `NETWORK_LLM_BASE_URL`、`NETWORK_LLM_MODEL` | `NETWORK_LLM_API_KEY` | 调用 `{BASE_URL}/chat/completions`；适用于经授权的远程兼容服务。 |
| 内置服务 | 无 | 无 | 始终可作为默认或外部请求失败时的自动回退。 |

自动模式的优先顺序为：已配置的本地端点、已配置的网络端点、内置服务。单个外部请求设有 15 秒超时；外部提供方不可用时，自动模式会继续尝试下一项，而手动选择某提供方时会如实返回其错误，避免将失败伪装成模型回答。

每个登录用户可在同一学习条目下创建多段个人会话、恢复历史或删除历史。模型调用始终附带当前页面的固定学习上下文，并最多附带最近 8 条已保存消息；单条历史内容会在服务端截断，避免会话无限增长或跨条目混入。历史仅在该用户的个人书案范围内读取和删除。

用户可在具体会话中手动生成“长对话学习摘要”。摘要使用当前会话的有限消息窗口和既有摘要进行整理，并保留“已确认线索、已获回答、待核对问题”的学习边界；其内容会作为下一轮会话的受控连续性线索。历史检索仅在当前用户的会话标题、摘要和消息范围内查找，不跨用户、也不把知识库文件自动提交给模型。

## 个人知识库

知识库入口为 `/knowledge`。系统仅接受 TXT、Markdown 或 PDF，单文件上限为 5MB；上传文件的字节数据通过服务端写入对象存储，数据库仅保存当前用户的文件名、类型、大小、对象键、访问地址与必要文本预览。TXT 与 Markdown 可以按标题和预览文本检索；PDF 暂不在站内提取正文，保留下载入口。下载前会先验证用户归属，再生成短期签名地址；删除操作移除当前用户的对象键和所有站内引用。上传或删除均不会自动将资料用于 AI 对话。

## 个人书案验证

登录后，请任选一则本草、经方或古籍条目进行以下人工验证：先点击“收入书签”，再新建一则笔记并进行编辑；最后进入古籍页标记阅读进度。打开“我的书案”后，应能看到对应条目的真实标题、类型、更新时间及跳转入口。该过程会写入你的个人学习数据，因此未由自动化过程代为执行。

### Cloudflare 验证边界

在发布域名的自动化验证中，Cloudflare 验证阻止了已登录会话接入。因此自动化过程**没有**新建、编辑或删除任何个人收藏、笔记与阅读进度，也就不需要清理测试数据。替代验证已覆盖三个层面：受保护 tRPC 接口的单元测试验证写入始终绑定当前用户；未登录浏览器验证确认个人书案不泄露内容；本草、经方、古籍检索及移动端交互回归已完成。若 Cloudflare 验证已通过，按上段“个人书案验证”执行一次即可完成真实账户验收。
